# Устройство проекта

Приложение использует Python 3.12+, стандартную библиотеку и SQLite. Логика акции отделена от сетевого клиента, поэтому её можно проверять локально.

| Модуль | Назначение |
|---|---|
| `config.py` | Настройки и проверка календаря |
| `db.py` | Таблицы, транзакции, резервные копии |
| `service.py` | Правила акции, розыгрыши, согласия, статистика, CSV |
| `messages.py` | Тексты и клавиатуры |
| `bot.py` | События и команды администратора |
| `vk.py` | Запросы API и загрузка баннера |
| `outbox.py` | Очередь и повторные отправки |
| `runner.py` | Long Poll и расписание |
| `demo.py` | Демонстрационный режим |
| `__main__.py` | Консольные команды и `.env` |

## Основные правила

- Ключ входящего события, изменения участника и ответ сохраняются одной транзакцией. Повторное событие не создаёт дублей.
- SQLite запрещает повторную выдачу кода пользователю за день и повторную регистрацию у партнёра. У каждого потока своё соединение.
- Розыгрыш сохраняет полный состав участников, веса, победителей и резерв. Для выбора используется `secrets.randbelow`; выбранный человек исключается из дальнейшего выбора.
- После подтверждения результатов создаются предложения призов и уведомления. Резерв используется в сохранённом порядке.
- Сетевые запросы выполняются вне транзакций. При повторной отправке сохраняется `random_id`. После 12 неудач сообщение остаётся в `failed` до ручного повтора.
- Позиция Long Poll и очередь сохраняются в базе. Прерванные отправки восстанавливаются после перезапуска.

Условия акции фиксируются в `settings`. Схема базы — `user_version=1`; изменения требуют миграции. Копирование работающей базы выполняется через SQLite Backup API.

Ключи, базы и выгрузки исключены из Git. Имена и ключи не выводятся в журнал. Административные команды проверяют права при каждом вызове.

Методы интеграции: Long Poll, `groups.isMember`, `messages.send`, `messages.isMessagesFromGroupAllowed`, загрузка фотографий. [Официальная схема API](https://github.com/VKCOM/vk-api-schema).
